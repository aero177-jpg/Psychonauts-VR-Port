## 2026-10-21 (later) — gameplay in stereo

**Astralathe 2.1.1 installed** (loads through dsound.dll, coexists with our
d3d9.dll).
CobwebDuster unpacked the game's assets to `native_assets\` (Lua 4 bytecode:
names readable as strings). Its first-run console spawned `cmd /c pause`, which
inherited our log handle and kept it locked — the log is now opened
non-inheritable ("wN").

**Test shortcut**: main menu level `st.STMU`; `MainMenuProcessSelection(2)` =
Continue (loads the latest save), 1 = new game, 0 = nothing seen.
`tools\astralathe_test_mod\PsyVRTest` hooks STMU's onPostBeginLevel to call it;
`Quick-Vr -Continue` installs it for the run, Stop-Psy removes it.
`LoadNewLevel` also exists (LevelScript) for jumping to levels.

**Focus pause**: 0x465440 = "game window in front" (GetForegroundWindow == game
hwnd), called by the pause-on-focus-loss and input checks. Patched to return 1
(`[window] pause_when_unfocused = 0`), bytes verified first.

**Game resolution**: the game sizes its scene render targets from
`DisplaySettings.ini` beside the exe (`[Global] ScreenWidth/ScreenHeight/
FullScreen`; default 800x600). At 800x600 the world went into an 800x600
target (mono) and only a copy reached the screen. The mod writes the VR back
buffer size there — but the game reads it before Direct3DCreate9, so a change
takes effect on the next launch.

**HUD composite lost the depth buffer**: a D3D9 state block does not hold the
render target or depth-stencil surface; Psychonauts binds its depth buffer once,
so after the first HUD frame the world drew without depth and the sky covered
everything. hud_draw_panel now restores both.

**2D classification**: 2D draws that sample any render target (320x240 glow
buffers) and Sprite.vsh full-screen triangles (c10 (2,-4), c11 (-1,1)) are
screen-space passes, not HUD.

## 2026-10-21 — first stereo in the simulator

**Hook.** Proxy d3d9.dll + DXVK fork loads and wraps the device. The game asks
for 800x600 fullscreen, flags 0x46 (HW vertex processing, MULTITHREADED,
FPU_PRESERVE); the proxy forces a window. Uncapped it runs ~240 fps on the
title screen (physics breaks above ~120: cap it).

**Present comes through IDirect3DDevice9::Present**, not a swap chain (Underworld
used the swap chain). ProxyDevice::Present now routes into
ProxySwapChain::Present, where the VR frame work lives.

**Present moves between threads.** Normally the main thread (which owns the game
window). During loading screens a loader thread presents, while holding the
game's global allocator lock (`CRITICAL_SECTION` at 0x791490, entered by
0x6846C0 / 0x6850A0).

**Deadlock (fixed).** The OpenXR session, and so the simulator's preview window,
is created on the main thread (CreateDevice). When the loader thread submitted
a frame, the simulator's xrEndFrame made a user32 call on its window → waited on
the main thread → which was waiting on the allocator lock held by the loader
thread. Fix: only the thread that created the session (`vr_submit_thread()`)
submits and waits on the runtime; other threads' Presents go to the monitor
only. A window-message guard was tried first and removed (it treated symptoms;
deferring WM_PAINT looped the simulator's pump forever).

Also learned: the simulator's xrWaitFrame runs `PeekMessage(nullptr)` (pumps
every window of the calling thread, including the game's).

**Projection recovered from WVP alone** (psy_stereo_math.h). The main scene uses
a 4:3 frustum, 66.1 x 52.0 deg at the menu, near 10, and depth term q = 0.990
(< 1: no far plane). Another pass uses near 0.1, far ~49355. Each eye's
projection uses the runtime's x/y and the game's own depth terms.

**Classification.** Draws reading c6 with a perspective WVP: per eye. Orthographic
WVP or no c6: 2D (virtual screen). Title screen: 22 draw groups per eye, 2 groups
2D, the rest on small (mono) targets.

**World scale.** Default 100 units/m (camera target height 110 in mod code
suggests centimetres). Not yet verified against a known object.

## 2026-10-21 — scale, horizon lock, camera settings

**Scale**: Raz's `height` = 125 units; a 10-year-old is ~1.25 m, so 100 units/m
(the default) is life size. The chase camera sits 735 units back (radius),
target height 150, pitched -14 deg.

**Game camera in memory**: Lua GetCameraPosition / GetCameraOrientation are
0x5690F0 / 0x569330 (found from their registration: `push name; push func`
at 0x6F11F4 / 0x6F1234). Both read `*(*(0x78BC20) + 0x8C98)` (0x4FA5A0 ->
0x4FA580: game + 0x8C98 + index*64): position vec3 at +0x08, quaternion
(x, y, z, w) at +0x20. Right-handed, camera looks down -Z, +Y up; q = yaw(Y) *
pitch(X) (verified against Lua's Euler -14, 145.5, 0).

**Horizon lock** (`[vr] horizon_lock`, live, default on): each Present the
camera quaternion is read and the eyes get the camera with pitch and roll
removed (a view-space rotation inside vr_eye_to_game_view). Verified: the view
comes up level, Raz lower in frame.

**Lua FOV units**: GetCameraFieldOfView = 2 x the vertical angle in degrees
(104 = 52 deg measured from the projection).

**PsyVR Astralathe mod** (mod\PsyVR, copied by install.bat): the proxy writes
its Scripts\Dart_hooks.lua at startup from psyvr.ini; Dart:onPostBeginLevel
(every level start) applies `[camera] chase_radius_scale` (default 1; 0.6
tested: radius 735 -> 441), `[camera] camera_shake` (default off) and
`[vr] cull_fov_degrees` (default 110 -> SetCameraFieldOfView(220); the game
then projects 138 x 110 deg and stops culling what horizon lock and the head
bring into view). Limits: applied once per level start; level scripts,
cutscenes and camera volumes may change radius/FOV later.

## 2026-10-24 — level name, menus and the D-pad

Current level name = string at *(0x78BC20) + 0x989A (Lua GetCurrentLevelName 0x5B4DE0): STMU = start menu, CAGP = camp, MMI1 / MMI2 / MMDM = Milkman Conspiracy. `[vr] horizon_lock_off_levels` (default `STMU MM`, prefixes) turns horizon lock off per level. ControlsArePaused = int at 0x78BB14 > 0, but it stays 0 in the pause notebook and the item wheel, so it is not used.

The pause notebook draws no 3D (menu screen); the item wheel (key 1 / D-pad left) draws a frozen copy of the scene as an opaque full-screen Sprite.vsh pass, then Raz per eye, with no clear. With `[debug] skip_fullscreen_passes` that copy was skipped and the eyes kept every frame: now an opaque full-screen pass that is the first draw into a stereo target in a frame is never skipped (the frozen background is then dark, since the passes that built it were skipped). Since 2026-11-15 that copy is replaced by black in every case (see that day).

The camera zoom's D-pad up/down is also how the pause notebook and start menu are navigated, so menus zoomed the camera and saved it; zoom input now only runs with no menu screen and outside STMU. In STMU `[camera] start_menu_zoom` (metres, default 1.5; the brain is ~2500 units from the camera) moves the eyes forward along the game view (vr_set_view_forward); the right stick changes it live there.


## 2026-10-24 — Quest controllers as the game's pad

The game imports XInputGetState / XInputSetState from xinput1_3 by ordinal (2, 3) into IAT slots 0x700414 / 0x700418 (.rdata) and calls them only through the thunks jmp [slot] at 0x6ECD8A / 0x6ECD90. game_psy.cpp checks those thunk bytes, makes the slots writable, and vr_pad_install (from DllMain) points them at vr_pad.cpp. The game picks keyboard or pad once at start-up, so the swap happens before the game runs and pad 0 reads as connected from the first poll (neutral until VR is up; off with `[controls] enabled = 0` or `[vr] enabled = 0`). Tested in the simulator with no real pad: a pad script walked Raz forward.

Touch lacks a D-pad and Back: `[controls] dpad_modifier` (default the left stick click, ported from Underworld's dpad_gesture) arms the left stick as the D-pad for one slide (left = item wheel, up / down = camera zoom); while armed the left menu button sends Back. The left menu button taps Start (tap) or opens the settings panel (held 0.6 s). With the controllers as the pad, the VR right stick is the game camera and no longer zooms. Untested on the Quest itself (the simulator has no controllers).


## 2026-10-24 — god mode (the world small, a seat on a leash)

`[god] enabled` (live). Ported from Underworld's board view (camera_rig): src/vr/god_seat.* is the pure maths (leash, seat pose, seat view -> game view), tested in mathtest.

**Camera internals** (Ghidra, on a local analysis of the Steam Psychonauts.exe): camera objects are 0xAB0 bytes in an array at *(game + 0x8C8C); the active one is *(game + 0x8C98). Type = int at +0: 0 fly, 1 script, 2 chase, 3 rail, 4 map, 5 sphere. Chase sub-mode +0x908 (0 normal, 2 first-person look). The camera update FUN_004CAEF0 (thiscall: cam, input, dt in **milliseconds**) switches on the type (chase = FUN_004DB540), then rebuilds the quaternion as a look-at from +0x08 to the target (FUN_004D1800) and builds the matrices (+0x90 world, +0x50 view = its inverse, +0xD0 projection). Chase azimuth is not stored (derived from position - target: offset = r(-sinA cosB, sinB, -cosA cosB), degrees); altitude base +0x96C plus offsets (+0x97C ease, +0x9F0 right stick, +0x9F8 / +0xA00); radius +0x968 + 0x974. Player entity = *(game + 0x818C); position = *(entity + 0x10) + 0x40.

**How god mode moves the camera**: a detour on FUN_004DB540 puts the seat into +0x08 after the game's chase update, so 4CAEF0 looks from the seat at Raz and the game culls and draws from there (no culling holes, also with the seat swung 180 deg). Before the next chase update the game's own position goes back (+0x08 and the previous-position copy +0x14), so its spring, collision and orbit never see the seat. Per eye only the rotation from the game's look-at to the level seat is added (vr_set_view_seat, asked at draw time); head motion and eye separation are scaled by 1.25 m / raz_height_cm (x8.3 at 15 cm). Frames with no chase update (script cameras, cutscenes, pause) are the game's own at life size. Right stick: x turns the seat round Raz, y zooms.

**Culling follows the head** (2026-11-03, `[god] aim_with_head`, live, default on). The game culls with camera +0x08 / +0x20 and the cull FOV (+0x30). Before, +0x20 kept the chase camera's look at Raz (about 30 deg down from the seat, and swinging up to ~30 deg sideways as Raz moves inside the leash) while the eyes looked level from the seat plus the head, so the top of the view and the side away from Raz lost objects, and so did any head turn past ~69 deg. Now, right after the chase update, +0x08 = seat + head position x scale and +0x20 = a no-roll look along the head's gaze (pitch held to +-75 deg; god_head_aim / god_look_quat); the game's own +0x20 goes back before its next chase update with the position. The chase update sets the quaternion itself: 4CAEF0's look-at FUN_004D1800 (thiscall camera, target; writes +0x20 and a copy at +0x8F8) ran 8 times in ~3000 chase frames. Simulator, head_yaw_test 70: off = trees, a trunk and grass missing on the left; on = all drawn.

Known gaps: no seat collision (in interiors the seat can sit behind a wall or above a ceiling); the left stick is relative to the seat's look-at, not the head's yaw.

**Start menu layers and the zoom** (2026-10-29). The start menu (STMU) draws, around the brain (~2700 units ahead of the game camera): a carousel of 12 line-art doodles (vs 884cf1, 92 tris each) whose centres swing between ~1350 and ~4000 units; credit speech bubbles (e4345d opaque + 9fb928 outline, scaled ~30x) that fly in from ~3300 to ~870; and the teal patterns / rectangle swirl, centred on the camera (c6.w = c7.w = c9.w = 0: the sky rule, at infinity). `start_menu_zoom` moves the eyes forward (1.5 m x world_scale: 750 units at world_scale 500), past the near side of the carousel and almost onto the bubbles. `[camera] start_menu_near_limit` (metres, default 2) moves a draw's eyes back so its centre (c9.w) stays at least that far away (psy_near_limit_shift); the brain keeps the full zoom, sky draws are untouched. Per draw, by its centre: a large mesh can still reach nearer with its edges. The draw log now records every register of 2..4-register constant uploads ("v").

**Menu screen size (2026-11-02)**: a world-locked menu was placed once at the distance of that moment, but its width followed the live setting, so dragging Menu distance while paused only shrank or grew it in place; the next pause re-placed it at the new distance and full angular size ("the pause menu resets to huge"). It is now put in front again when menu_distance changes, like the settings panel. `[hud] body_locked` (default 1): the gameplay HUD stays at the room's forward (recentre yaw), level, `distance` ahead of the head's position.


## 2026-11-15 — horizon lock modes, god mode culling, targeting

**Horizon lock** (`[vr] horizon_lock`) is now `off`, `auto` or `on` (0, 1, 2 also read; the old `1` is `auto`, so existing ini files keep their behaviour). `auto` = locked except in `horizon_lock_off_levels` (default `STMU MM`), `on` = locked everywhere, `off` = the game's camera. The settings panel has a combo for it.

**How the game culls** (Ghidra, 4CAEF0 near 0x4CD2C1): every camera update builds the projection with D3DXMatrixPerspectiveFovRH(+0x30 / 360 x pi, aspect, near +0x48, far +0x4C) into +0xD0; aspect = 4:3 if width +0x40 is 640, else +0x40 / +0x44 (1920 x 1080 here, set from the game's own resolution, not our back buffer). FUN_006A04F0 then builds the frustum (6 planes and 8 corners) at camera + 0x234 from the NDC cube times (+0x90 camera matrix x +0x110 inverse projection). So +0x08, +0x20 and +0x30 written in the chase update detour are what it culls with, the same frame.

**God mode culled on-screen things at the view's edges.** The simulator's eyes are 110 deg symmetric, exactly the default `cull_fov_degrees` 110, and a Quest 3 looks 54 deg down against the frustum's 55: no room at the bottom. The game's test does drop things at the frustum edge: with the head held still, writing +0x30 (Lua units) 220 vs 300 showed tree foliage at the top of the view missing at 220. The gaze's pitch was also held at 75 deg, so looking straight down the bottom 14 deg of a 110-deg view lay outside a 110-deg frustum. Now, in god mode with `aim_with_head`, the cull camera aims at the middle of the eyes' view (Quest 3: 5 deg below the gaze, `god_cull_pitch_offset`), its +0x30 is held at the eyes' view plus 10 deg on every side (`god_cull_fov_lua`: 260 on the simulator, 236 for a Quest 3) and put back with the quaternion before the next chase update, and the pitch limit is 89 deg with the heading steadied by the head's up vector near vertical (as steady_yaw_of). Checked: sweeps at zoom 0.25 / 1 / 4 (pitch 0 .. -89, yaw 60 / 180, lean, up 30) show no holes; Run-Smoke passes.

Side notes from the measurements: 358 (179 deg) is not a usable no-cull reference: the near-degenerate projection lets light shafts (translucent beams) through that are normally hidden. At zoom 4 on `reception` the seat sits inside a tree canopy (no seat collision). The second projection in the stereo log, 137 x 61.5 deg, is a per-draw read of the WVP (sx the same, sy 1.68), most likely a draw with a scaled world matrix, not a second cull frustum.

**Targeting on `circus`, provisional** (simulator, scripted pad): the `circus` save loads at the start of the level, and the creature next to Raz there is **not an enemy**, so nothing below has been checked against an enemy. Lock-on is the right trigger (LT did nothing visible). Locking onto the creature puts an orange 3D marker on the ground under it, drawn in the world, so it is at the creature's depth in both eyes; it locked in normal and god mode, also when pressed with the head turned 90 deg away. B (held lock) puts a green beam from Raz's hand to it, the same in both eyes. RB / LB showed nothing in the shots. The "Teleport Options" prompt and the ammo / power icons draw in both eyes. To do with a real enemy: lock-on, the reticle, powers, free aiming, the first-person look mode.

**God mode's camera logic moved into the logic DLL, for hot reload.** Until now only the stereo drawing reloaded; the chase-update detour (seat, stick, head aim, cull FOV) was in the shim, so every culling experiment cost a relaunch and a minute of loading. Now the shim keeps the hook on 0x4DB540, reads Raz, the camera rotation, the pad, the head and the eyes' FOV into `GodFrameIn`, and calls `god_frame` (src/vr/god_frame.cpp, in psyvr_logic.dll). The logic returns the seat for the draws and a list of camera writes; the shim saves the bytes they replace, applies them, and puts them back (last first, then +0x08 copied to +0x14 if the position was among them) before that camera's next chase update. Same behaviour as before (checked: seat on, 260 cull FOV on the simulator); changing the margin to 15 deg and `Push-Logic` gave 140 deg vertical in the frame of the swap (47 ms), no relaunch. ABI 9.

**Open: the god mode culling fix did not work in the headset** (user report, same day; details not yet given). The simulator sweeps showed no holes, so the headset differs in something the simulator does not reproduce. Next: get from the user where things vanish (bottom edge, sides, straight down; near or far), at what zoom, and whether fast head turns make it worse; then reproduce with `Psy-Sweep` on `reception` and iterate in `god_frame.cpp` with `Push-Logic`. Leads to check: the real headset's asymmetric FOV and wider aspect against the camera's +0x40/+0x44 aspect (`god_cull_fov_lua` caps at 89 deg a half); a frame of lag between the cull camera (head pose read at the chase update) and the eyes (pose at draw time) on fast turns, which the simulator's scripted poses do not show; culling that does not use the +0x234 frustum at all (per-object distance or portal/sector culling, which a wider FOV would not fix); and whether `aim_with_head` is on in the player's ini.

**Classic-view flicker and tree fades: occlusion queries seen through the eyes** (user report: in classic view, pitching the head makes the sky flicker and some not-so-distant trees fade in and out in the middle of the view). The game creates D3D occlusion queries (type 9) and fades things by a ratio of two of them: visible / total pixels of a box, clamped 0..1, stored at item +0x3C. Lights at 0x517949 (query ids 0x19B8 total, 0x19B9 visible, up to 12 items: the sun glare in `reception`) and per object at 0x449C72 (ids 0x20 + n and 0xCEC + n, n = entity +0x0C). A total of 0 sets the visibility to 0 (hidden). The query wrapper is 0x67AC00 (Issue begin, caller 0x67AC91) / 0x67ACB0 (end) / 0x67AD20 (GetData by id). The box draw (12 tris, z test on, z write off, colour blended away) is classified "camera, per eye", so it is counted in the eyes' views: on `reception`, pitch -40 / -20 / 0 / +20 gave 17004 / 14654 / 18383 / 35783 pixels and +40 gave 0, where the game's own view still has the box on screen. So a head turn that takes a box out of both eyes (the box of a tree near its base while you look at its canopy) faded the object. Fix (src/proxy/proxy_query.h, shim): in stereo a GetData of 0 reads 1, so off-screen counts as visible; on screen and behind something still gives a ratio near 0. Checked: +40 reads 1, Run-Smoke passes. Not yet seen in a shot: on `reception` the only queried item is the sun glare and no fade showed at +40; the tree fades need the headset (or a spot with queried objects) to confirm. The wrapper also writes Issue / GetData lines into the draw log (`Psy-Cmd "drawlog name"`).

## 2026-11-16 — theatre: a 3D screen with the game's own framing

**Why the old theatre warped.** It was a hole in the wall: the eyes were the immersive view's (game camera + head pose), each eye scissored to the window's bounding box in that eye's image. The box is axis-aligned in the eye image, so with the head turned or rolled the "window" changed shape and tilted with the head; and what showed through it was a head-tracked crop of the world at the headset's lens, not the game's framing (user: "the theatre frame warps with our headset").

**Now (src/vr/psy_theatre.h, as the Underworld mod's theatre but a fixed 3D screen).** While the theatre shows, stereo.cpp's camera draws use virtual eyes from the shim (`game_theatre_eyes`, logic ABI 17): the game camera itself, each eye moved sideways by half the real eye separation x `[theatre] depth` (game units, [vr] world_scale), and a projection with the game's own vertical scale sy (recovered from WVP) at the screen's aspect, shifted in NDC x by eye_x / screen half width so infinity lands one eye separation apart on the screen (uncrossed, at infinity). With the screen as tall as the game's view a point at screen distance x world_scale lands on the screen with no disparity: life size. No head pose, horizon lock, forward offset or god seat goes in. At Present (`hud_theatre_screen`, before the HUD) the back buffer is copied (StretchRect into a back-buffer-sized RT texture), the eyes cleared to the dark room (12, 12, 14), and each eye's half laid on a quad fixed in the room (`hud_draw_panel_eyes`, opaque), seen with the real head pose. The screen is placed level at head height `distance` ahead of the head when the theatre opens, at a recentre and at a new distance; the HUD lies on it (1 cm in front, as tall), menus without a scene keep the menu screen. Mathtest checks the geometry (infinity = one eye separation apart, screen distance = zero disparity, twice as far looks twice as far, depth 0 = flat, depth 2 never diverges).

**When it shows.** `[theatre] mode` (live): 0 off, 1 cutscenes (default), 2 always. Mode 1 = the camera the game draws with, *(game + 0x8C98), is the script camera (type *(int*)camera == 1), not in the start menu (which uses one too). The types are the Lua constants registered at 0x6FE9xx: kCAMERA_FLY 0, SCRIPT 1, CHASE 2, RAIL 3, SPHERE 5; rail and sphere cameras are gameplay cameras, so they stay immersive, held 3 frames before it opens or closes. Seen in the simulator: type 1 in the intro videos and the start menu, 2 in gameplay. Cutscene camera types are not yet confirmed in a real cutscene: the log has every change (`theatre: the game's camera is now type N`). The old `enabled = 1` reads as mode 2, `enabled = 0` as the default.

**Classic while it shows.** `chase_view` returns -1 (no god seat, no level seat, no head aim) and `horizon_lock_applies` is false while the theatre shows, so god mode and horizon lock show the game's own camera; they come back when it closes. The culling FOV (+0x30) is not widened then: `hold_settings_frame` puts back the game's own value, the last one narrower than `[vr] cull_fov_degrees` (ours, the Lua hook's at level start and god mode's are never narrower; unknown = 104, the chase camera's 52 deg), so the recovered projection is the game's own, cutscene lenses included. A first version took god mode's 260 for the game's own and showed the classic view at 130 deg; fixed. Simulator (gpc, 1280 x 1400 eyes): mode 2 shows 52 deg on a 3.5 x 1.97 m screen at 2.5 m; head sweeps (yaw +-30/70, pitch +-30, roll 20) move and tilt the screen as an object in the room with its picture unchanged; god on + mode 2 = the classic picture at 52 deg; mode 0 (god mode running) -> 2 live gives the same picture again (mean difference 0.02); smoke PASS with mode 1.

**Cost.** The old theatre saved GPU by scissoring; this one renders the whole eye images (the game's frame at the eye's full resolution) plus one copy and two quads, so it costs about what immersive does. Rendering the eyes smaller for the screen is possible later.

## 2026-11-16 — view reset on the right stick tap

A tap of the right stick click no longer sends R3 to the game (its first-person look is in the view switch); it resets the view (user): the camera glides behind Raz at its own height, keeping the zoom and Raz's size. **The chase camera's orbit.** Lua SetChaseCameraAzimuth (wrapper 0x56D600 -> 0x56D660) calls FUN_004E3990 (thiscall: camera, azimuth in degrees; with an entity argument Lua adds that entity's heading first) and the camera moves there at once (+0x08). Altitude = +0x96C (SetChaseCameraAltitude, 0x4E3A20; 14 deg here) + +0x9F0, the right stick's orbit up / down in degrees (45 -> 59 total, -5.8 -> 8.2, found by diffing the camera object before and after an orbit). Other natives found: MoveCameraToIdeal 0x56A6B0 (-> 0x4CD6D0), ResetCameraMode 0x56A740 (-> 0x4CD9D0), GetChaseCameraAzimuth 0x56D7F0 (0x4D5130 = the camera's spherical offset).

## 2026-11-16 — theatre window style (`[theatre] style = 1`)

The screen style is a 3D TV: fixed stereo, head movement changes nothing in the picture (user: "more of a 3dof experience"). The window style is a window you can look into, as the Underworld mod's theatre with fit_fov (user's choices: fit the game's shot; horizon lock and god mode classic, as in the screen style).

- **Eyes.** The real eyes, relative to the anchor: the head where the window was placed (`hud_theatre_window`, now also asked by the eyes so the first frame has it), `distance` straight back from the window's centre. The game camera is the anchor, looking through the window (game view space = the window's frame). `game_theatre_eyes` gives each eye -> game view (translation x world_scale) and the fit scale (TheatreEyes, logic ABI 19).
- **Fit.** The world is warped about the game camera by diag(s, s, 1) in game view space, s = tan(window's half height from the anchor) / tan(the game's half vertical view) (`theatre_fit_scale`, `theatre_fit_warp`), so from the anchor the window shows the game's whole shot and cutscene lenses zoom; depth along the view is kept (something at distance x world_scale lies on the window). Per eye: view_to_eye = warp x inverse(eye -> view), the headset's own projection with the game's depth terms; skies drop the translation (still at infinity under the warp). Mathtest: the game's frame edge lands on the window's edge at any depth.
- **Cut-out.** At Present the back buffer is copied, the eyes cleared to the dark room and the window's quad drawn per eye with each corner sampling the pixel it lands on (`screen_uv`, rhw 1 so the lookup is linear on screen): the window's exact outline, whatever the head does.
- **Culling.** The game's own field of view is tracked (`g_theatre_game_fov_lua`, the last value narrower than ours that is not the theatre's own write) and used for the fit, since the projection recovered from WVP is now the widened one; the camera culls 1.6x wider in tan (52 -> 76 deg vertical, Lua 152), capped at `[vr] cull_fov_degrees`.

Simulator (gpc, mode 2): leaning 15 cm sideways keeps the frame (almost) still and shifts near things inside it by up to 27 px against far ones; 0.8 m forward the window grows and shows more round Raz; turned and rolled the frame stays in the room, cut exactly; from 1.6 m forward and 0.6 m to the side, turned to it, the scene is seen at an angle well past the shot's edges with nothing culled (one small dark notch in the sky at the frame's top-left corner, probably the sky dome's edge, not looked into).

**Glow looks slatted / segmented: the fixed 320 x 240 glow target undersamples (2026-11-16)**. **What the full-screen passes cost: fading objects, two whole-frame passes each (2026-11-16)**.
